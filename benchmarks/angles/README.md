# 换角度验证：工具衔接、技能有无与推理档位

日期：2026-10-25（Asia/Shanghai）。本轮包含 **4 次工具兼容性复现 + 32 次技能/档位交叉对照**。正式技能仍为原版 94 字符，未修改正文、全局模型设置或权限。[四组数据](results.json) · [预定计划](plan.json) · [冻结任务](tasks.json) · [旧轨迹诊断](prior-diagnosis.json)。

## 找到的具体原因

**查看工具与写入器的读取记录不互通。** 上一轮 F02 用 ops_inspect_local_file 查看文件后，原生 write 仍报 file has not been read；补读和重写两个请求的实际 usage 合计 29,528 token。这个数字是已发生的恢复请求消耗，不是修复后必然节省的反事实估计。

本轮用四个新会话、独立 marker.txt 复现：先 inspect 的两次均首次写入被拒，原生 read 补读后成功；先原生 read 的两次均首次写入成功。四次最终文件及受保护说明均正确，无 shell/edit 调用。[协议与观察](read-guard/plan.json) · [复现结果](read-guard/results.json)。

可采用的项目约定是：**准备交给原生 write 修改的文件，先用原生 read 读取；预览不替代此步骤。** 适用的宿主/插件范围、复制用语和局限见 [工具衔接参考](../../docs/HARNESS-TOOLS.md)。该提示尚未作为新正文做通用成本对照，未混入后面的四组实验。

**额外请求会重复携带上下文。** 上一轮 F01 首次输入已有 8,962 token，工具清单有 30 项，说明 JSON 序列化长 24,783 字符。字符数不是 token 数，不能据此计算各组件的 token 占比。F07/F14 在规定 unittest 通过后又执行了额外检查；F07 还检查了合同输入域已经排除的循环对象。额外检查是否值得，应按任务合同和风险判断，不能把所有验证一律删掉。

## 四组交叉结果

沿用上轮四个冻结任务，每组每任务两个独立会话，共 8 次/组、32 次。所有组都完成规定测试及外部验收，32 次实际技能加载/不加载记录均符合分组，没有失败的技能查找调用。

- **无技能 + High**：719,829 token，55 次模型请求，71 次工具调用；未缓存输入 40,080、缓存读取 651,136、输出 28,613；总耗时约 225.5 秒。
- **正式技能 + High**：460,588 token，42 次请求，58 次工具调用；未缓存输入 32,679、缓存读取 414,848、输出 13,061；约 149.9 秒。
- **无技能 + Low**：505,466 token，44 次请求，57 次工具调用；未缓存输入 34,360、缓存读取 451,328、输出 19,778；约 214.8 秒。
- **正式技能 + Low**：448,748 token，42 次请求，56 次工具调用；未缓存输入 32,151、缓存读取 406,400、输出 10,197；约 118.0 秒。

四个预定比较分别是：

- 在 **High** 下加正式技能：总 token 少 **36.01%**，赢 **8/8** 配对；四个任务合计都下降，达到本轮预设推荐门槛。
- 在 **Low** 下加正式技能：少 **11.22%**，赢 **5/8**，未达到至少 6/8 的稳定性门槛。
- **无技能**时 High 改 Low：少 **29.78%**，赢 **7/8**，达到本轮门槛；路径任务合计略多 0.56%，仍在预设 5% 容忍范围内。
- **已有正式技能**时 High 改 Low：只再少 **2.57%**，虽赢 **6/8**，但未达到预设总量至少减少 10% 的门槛。

这些是本轮四个任务的描述性结果，不是保证收益或统计显著性结论。技能与降低档位的效果在本次并不简单相加：无技能 High 的额外步骤较多，短技能与 Low 分别减少了一部分开销；已有短技能后，再改 Low 的总 token 增益很小。这里的机制解释是从可见轨迹与分组结果作出的推断，不证明内部推理过程发生了何种变化。

## 轨迹支持了什么，尚不能说明什么

无技能 High 出现 3 次原生写入“未读取”拒绝，无技能 Low 出现 1 次；两个有技能组本次均未出现。规定 unittest 首次成功后，后续工具调用次数分别为 4、1、2、0（顺序为无技能 High、技能 High、无技能 Low、技能 Low）。它们可能是额外检查，不能只凭次数认定每次都无必要。

无技能组首个请求输入均为 8,938 token，有技能组均为 8,974，相差 36。此时技能正文尚待工具加载，不能把 36 当成 94 字符正文的 token 数。本轮没有因为技能额外执行一个失败查找；可用性描述、实际加载、后续请求和上下文共同构成安装技能这一干预的成本。

模型请求从 55 降到 42 是实测的行为差异；不能把全量 36.01% 都归因于某一次写入错误，也不能据此声称内部推理能力增强。usage 没有单独给出推理 token；输出包含生成内容等开销，不能等同于最终回答长度或隐藏推理长度。

## 控制条件和边界

完整方案在执行前固定：四个任务 × 技能有/无 × High/Low × 两次重复。以任务与重复构成四臂相邻区组，用 Python random.Random、种子 2026102501 随机首轮顺序，第二轮反转；每轮随机任务顺序。没有统计功效计算。预设推荐条件为：比较双方质量和分组执行全部通过、总 token 至少少 10%、至少赢 6/8 配对、各任务至少赢一次且任务合计退化不超过 5%。

四组使用相同条件式请求：“若系统提供 deepseek-efficient 技能，先使用；否则直接执行。”本轮测的是**安装、发现、加载及使用技能的整条路径**，不能独立分离正文文字的效果。没有给不同组不同的验收合同。四个任务全部来自上轮冻结夹具，未用于本轮改写提示；本轮也没有新候选文字，因此不能作为新任务泛化检验。

初始错误实现均作负对照，32 个初始目录逐个被规定测试拒绝，以平衡测试缓存。模型产物均由新进程复跑冻结测试，共 336 次 unittest 方法执行（同一方法重复使用，不是 336 个独立测试）。受保护文件和新增文件检查通过，测试缓存除外。模型实际执行测试及路由/档位来自私有轨迹观察；公开产物可以复跑代码正确性，不能独立证明全部调用 usage。

本轮结束时核验安装包为 **Harness 0.2.1-rc.3**，dsh-ops 0.3.0；所有调用使用同一路径的桌面包 headless 入口。之前报告记录 rc.2，数据不合并。二进制未做快照固定，版本是在本轮结束后检查；代理没有发起升级。各次请求头均核验 deepseek-account/deepseek-flash 及所分配的 High/Low。

每次最多 240 秒，运行器不自动重试。全部正常结束，没有排除失败运行；模型内部的错误与恢复计入 usage。启动器仅清理子进程继承的 PSModulePath。两组读取工具复现与四组技能/档位比较分开统计，没有改全局权限、工具清单或桌面默认档位。

缓存热度无法固定；首次输入、未缓存输入、缓存读取与输出均单独报告。usage 为已提交 assistant 请求之和，缺失 usage 的会话命名和在途请求不伪造。没有真实计费口径，因此不作费用承诺；耗时含服务端等待与环境开销，不是纯模型计算时间。DeepSeek 的缓存和推理档位机制见 [官方缓存文档](https://api-docs.deepseek.com/guides/kv_cache/) 与 [官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 复跑方式

Python 3.10+，仅标准库，离线验收会执行可信的 Python 产物：

```powershell
python benchmarks/angles/fixture.py evaluate paths benchmarks/angles/artifacts/A01/paths.py
python benchmarks/angles/fixture.py prepare patch skill_low ../skill-low-trial
python benchmarks/angles/read-guard/prepare.py ../read-guard-trials
```

prepare 只允许不存在的新目录，技能目录按分组生成；High/Low 需要在宿主另行选择。读取检查生成器建立四个独立 marker 项目，不调用模型。真实模型复测按 plan.json 使用全新会话和相同请求，保留全部失败、usage 与产物。私有执行配置和凭据不在公开资料中，工具衔接复现需使用计划里指定的工具组合。

实验安排参考 experimental-design 技能；文库来源：Kassis, T., Agarwal, V., He, Y., Patel, D., & Brueckner, A. M. (2026), [Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents](https://doi.org/10.48550/arXiv.2609.00065)。该出处不证明本技能的效果。
