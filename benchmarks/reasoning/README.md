# 以验收和不确定点为中心的候选提示

2026-10-24 的探索性比较。**候选可供隔离试用，尚未替换正式 SKILL.md。** [逐次数据](results.json) · [事先固定的计划](plan.json) · [冻结任务](tasks.json) · [提示快照](../prompts/reasoning-guided.txt)。

## 候选如何改变决策

将可描述的任务处理策略写成 99 字符正文：先明确交付与约束，只解决会影响结果的疑点，用验证检查关键假设，在出现新证据或验证失败时调整，满足验收后完成交付。没有复制其他模型的内部推理，也没有要求模型输出隐藏思考过程；提示只能影响行为，不能移植模型能力或硬性控制内部 token。

```text
以交付和约束为准，只追查影响结果的不确定点。选择最短可行路径，用必要验证检查关键假设；遇新证据或验证失败再调整。验收满足即交付，不反复复述或比较等价方案。保留复杂任务所需的分析与用户要求的全部交付。
```

对照为正式版的 94 字符正文；前置信息、模型、High 档位、工具和任务合同一致。这次测试的是整段改写，不能把结果归因于其中某一句话。

## 结果与保留为实验版的原因

两个新任务族，各两次独立配对重复，共 8 个新会话：

- 原版总 token **299,009**；候选 **264,786**，本次合计减少 **11.45%**。
- 模型请求 **27 → 24**；工具调用 **34 → 33**。
- 输出 token **7,019 → 7,476**，增加约 **6.51%**；耗时合计约 **74.2 → 73.0 秒**。输出没有变得更短，耗时也未显示明显改善。
- 8 个产物均通过外部验收和指定终端测试，共 88 次 unittest 方法执行；相同方法在各组重复，不是 88 个独立测试。测试、合同及技能文件哈希保持原样。

四个配对的候选 token 降幅依次为：依赖排序第 1 次 **0.45%**，依赖排序第 2 次 **−4.18%**，转账第 1 次 **−4.91%**，转账第 2 次 **37.58%**。负数表示更费 token。

运行前固定的采纳条件是：8 次质量检查全部通过、候选总 token 至少减少 5%、四个配对至少赢三个。**实际只赢两个，因此不采纳为正式版。** 总量改善主要来自一次转账对照；仅看总量容易高估稳定性。全部 8 次均保留，包括原版一次工具报错及其后续恢复的消耗，没有筛掉表现较差的运行。与之前实验的模型用量不混合计算。

## 设计与验收

候选正文先冻结，再创建这两个任务；没有用它们的结果调整候选措辞。按“任务 × 重复次数”分成四个相邻配对区组。使用 Python 标准库 random.Random、种子 20261024，为每个任务随机确定首个顺序，第二次反转顺序，使每种提示在各任务都先运行一次。完整顺序与软件版本在 plan.json。没有进行统计功效计算或显著性检验，这只是小规模筛选。

- **依赖排序**：动态字典序选择、依赖方向、重复边、非法输入、循环检测和输入不变性。10 个 unittest 方法，其中独立穷举三节点有向图的 64 种边集合，用排列搜索作验收依据。
- **幂等转账**：重复事件、冲突 ID、转账顺序、自转账、余额不足、严格输入校验和失败时不修改输入。12 个 unittest 方法，包括固定种子的有效转账序列。

初始错误实现作为负对照，两个都未通过。每次会话还要求真实执行 python -m unittest -v，并核验终端工具成功和 OK 标记；模型路由与 High 档位从请求头确认。公开的 [8 份产物](artifacts) 可由独立进程重新运行冻结测试；运行轨迹相关检查是本机观察，公开代码复跑不能证明轨迹或全部 token 用量。

环境：DeepSeek Harness 0.2.1-rc.2 桌面安装包 headless 入口，deepseek-account/deepseek-flash/High，dsh-ops shell/file 0.3.0。每次最长 240 秒，不自动重试，不修改全局设置。仅去除启动子进程继承的 PSModulePath，避免已知 PowerShell 模块冲突，两组一致。

token 为已提交 assistant 请求 usage 的输入、缓存输入、缓存写入和输出之和，包含工具错误及恢复。没有 usage 的会话命名请求和未返回 usage 的在途请求无法计入。原始私人会话档案不公开，哈希仅供本机追溯。这是单模型、两个任务、单轮 headless 观察；未证明普遍收益、推理能力提升、长会话效果或 GUI 端到端性能。两组都加载技能，不能据此计算相对“无技能”的节省率。

## 离线复跑与隔离试用

Python 3.10+，仅标准库，无模型或联网调用。验收会执行指定的 Python 代码，只对可信文件运行。

```powershell
python benchmarks/reasoning/fixture.py evaluate graph benchmarks/reasoning/artifacts/R02/planner.py
python benchmarks/reasoning/fixture.py evaluate ledger benchmarks/reasoning/artifacts/R04/ledger.py
python benchmarks/reasoning/fixture.py prepare graph candidate ../reasoning-candidate-trial
```

prepare 的目标目录必须不存在。它在新目录生成合成任务和项目级候选技能，不会修改已安装的正式技能。在 Harness 打开新目录，手动保持 Flash/High，使用 plan.json 中的同类请求即可试用。若要用于自己的任务，将提示快照保存成隔离项目的 .agents/skills/deepseek-efficient/SKILL.md，保留完整前置信息；同一项目只放一份同名技能。
