# 研究驱动的日志优化：原型与修复复测

2026-10-25，Windows DeepSeek Harness 桌面自带 headless 入口，宿主与核心 0.2.1-rc.3，dsh-ops 0.3.0，deepseek-account / deepseek-flash / High。研究依据及未采用方法见 [来源与取舍](../../docs/RESEARCH.md)。

## 结论与当前能力

完整代码验收 16/16 通过，168 次 unittest 方法复跑。只读日志脚本已能在本轮 Harness 内正常使用，但把它的说明加入每次加载的技能正文没有降低端到端总 token。因此正式正文保持 94 字符、字节不变；安装包新增 [可选日志工具](../../references/log-output.md)，不默认给所有任务增加日志流程。

不能把“日志反馈变短”表述为“模型更省 token”。这些是复用合成任务的小样本工程诊断，未证明通用节省率或推理能力改善。

## 冻结设计与证据

每阶段分别是两个任务（quiet、verbose）× 原版/候选包 × 两次重复，共 8 个独立会话。quiet 复用 paths 合约（10 个方法）；verbose 复用 join 合约（11 个方法），额外生成 1500 行明确无关的合成进度文本。原命令都是完整的 python verify.py，测试和验证脚本冻结；允许本地保存 .agent-evidence/ 日志。

每阶段在采集前固定顺序和门槛：全部质量通过、候选总量 ≤ 原版 95%、至少赢 3/4 配对、quiet ≤ 105%、verbose ≤ 90%，两次 verbose 候选都须真正成功使用辅助脚本。随机第一重复的相邻配对顺序，第二重复反向；Python random.Random，原型种子 2026102502、修复种子 2026102503。没有按观测结果换门槛或追加重复以追求胜出。

## 原型失败：子进程启动成本

原型让 Python 辅助脚本启动原命令，再返回日志摘要。本机普通终端的单元测试通过，但两次 Harness 长日志候选中的子进程返回 3221225794（0xC0000142），日志零字节；原终端直接运行则能验证完成。这里仅确认启动兼容性失败，没有进一步断言 Windows 底层原因，也没有放宽沙箱或权限。

模型通过原终端重跑完整验证，所有最终代码通过；失败、诊断、补救都计入成本。原版 257,952 → 候选 329,892，总 token **增加 27.89%**；仅赢 1/4 配对；长日志组增加 50.07%。没有采用。

## 修复复测：返回量改善，总量未改善

修复改为原终端完整执行并捕获状态，Python 脚本仅读取已完成的日志，不创建原命令子进程。两次长日志候选都成功使用，日志哈希、字节数、完整测试数及 OK 证据相符；8 个质量验收全部通过。

原版 249,645 → 候选 274,674，总 token **增加 10.03%**，仅赢 2/4 配对；quiet 增加 21.68%，verbose 增加 1.66%，未达到预定门槛。

修复阶段的长日志验证相关工具反馈从 6,562 → 2,580 字符（少 60.68%）。全部工具反馈 26,743 → 23,204 字符；模型请求 22 → 25，工具调用 34 → 36。总量差额主要体现在缓存读取 225,152 → 250,624，未缓存输入反而 17,205 → 16,934、输出 7,288 → 7,116。额外往返会携带已有上下文，不能只优化一段输出长度。

字符指标按命令字符串涉及 verify.py、辅助脚本或 .agent-evidence 日志的工具结果分组，包含相关脚本读取和后续日志查询，不是 tokenizer 统计或单独思维 token。原版也自行重定向日志、用 tail/grep 摘要，不能把它描述为“总是把全部 1500 行交给模型”的基线。

因此把脚本作为显式可选工具，短任务无需额外说明或调用。两阶段分别分析，不把原型与修复配对混算为新的效果。

## 测量修正与可复验范围

初始收集器只在即时工具尾部寻找 OK，遗漏 stdout 缓冲导致“测试汇总先于大量进度文本出现”的情况。修正版额外核对本次完整留盘日志，并把“完整验证通过”与“辅助脚本成功采用”分别记录；原型辅助调用仍判失败。没有重跑模型、删掉失败请求或修改 usage。公开结果标识测量修订。

日志标记可能出现在文件中部，摘要器保留最多六条带行号的常见 unittest 标记。标记只是导航信息；原退出码必须由调用方立即捕获，脚本不能独立证明它正确。测试覆盖完整日志哈希、长尾缓冲、失败状态、路径约束、中文及超长行等行为。

离线执行：

```text
python -X utf8 benchmarks/research/check.py
python -X utf8 scripts/check_repository.py
```

可复跑 16 个代码产物、错误代码负对照，校验冻结文件/提示/脚本哈希、逐请求用量与汇总、配对结果和采纳门槛。原始模型会话、私人路径和完整日志不公开；archive_sha256 只用于识别留存的私人证据，公开数据不能独立证明所有模型调用或费用。

两次重复不足以估计稳定的泛化效果。1500 行是合成压力日志，不能对应生产日志节省率；宿主工具本身也可能限制返回长度。没有删除必要推理、协议字段或测试来减少用量。
